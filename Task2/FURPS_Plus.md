# FURPS+ Таблица требований — Банк «Стандарт»

## Цифровая трансформация: онлайн-депозиты и онлайн-кредиты

| Код | Требование | Комментарий |
|-----|-----------|-------------|
| **F** | **Функциональные (Functionality)** | |
| F-1 | Клиент видит в интернет-банке список доступных депозитов с актуальными ставками и персонализированными условиями | Персонализация ставок требует расчёта на основе данных клиента и кредитного риска банка |
| F-2 | Клиент подаёт заявку на открытие депозита в интернет-банке, указав счёт и сумму; операция подтверждается СМС-кодом | Функционал СМС в ядре интернет-банка требует доработки подрядчика — лучше реализовать новым компонентом силами команды банка |
| F-3 | На этапе MVP заявку на депозит обрабатывает менеджер бэк-офиса в АБС, подтверждая условия | Промежуточное состояние (6 месяцев), позже — полная автоматизация |
| F-4 | Клиент получает СМС-уведомления после подтверждения ставки и после открытия депозита | Требуется интеграция нового процесса с СМС-шлюзом |
| F-5 | На сайте новый клиент видит список депозитов с актуальными ставками и может подать заявку, указав телефон и ФИО | После подачи заявки менеджер кол-центра связывается с клиентом |
| F-6 | Ставки по депозитам ведутся в единой системе, доступной для бэк-офиса депозитов и бэк-офиса кредитов | Сейчас ставки рассчитываются вручную в Excel; нужна автоматизация, возможно в рамках АБС |
| F-7 | Через год — депозит открывается полностью автоматически без участия бэк-офиса; при обращении в отделение — без бэк-офиса | Целевое состояние на 12 месяцев |
| F-8 | На сайте клиент может подать заявку на кредит (телефон, ФИО, опционально паспортные данные); при наличии паспорта — мгновенное предварительное решение | Для предварительного решения используются только данные БКИ (клиент новый) |
| F-9 | В интернет-банке клиент видит список кредитов с условиями и предодобренные предложения (на основе ранее проведённого скоринга) | Предодобренные предложения требуют фонового расчёта скоринга |
| F-10 | Клиент подаёт заявку на кредит в интернет-банке, указав счёт зачисления и данные; операция подтверждается СМС-кодом | Аналогично депозитам — избегать доработки ядра интернет-банка подрядчиком |
| F-11 | Заявки по предодобренным предложениям обрабатываются в течение того же рабочего дня | Текущая интеграция АБС→Кредитный конвейер раз в сутки — нужен альтернативный канал передачи |
| F-12 | При визите в отделение менеджер продолжает работу с заявкой, поданной клиентом онлайн (с сайта или интернет-банка) | Требуется единое хранение заявок, доступное и онлайн-каналам, и отделениям |
| F-13 | СМС-информирование клиента об изменении статуса заявки на кредит | Интеграция кредитного конвейера с СМС-шлюзом |
| F-14 | После подачи заявки на кредит с сайта клиенту приходит СМС о необходимости визита в отделение для идентификации | Новые клиенты не могут быть обслужены без личной проверки документов |
| | | |
| **U** | **Удобство использования (Usability)** | |
| U-1 | Интерфейс максимально удобен для клиента; отклик по всем операциям — в миллисекундах | Бизнес-ожидание; требует оптимизации фронтенда и бэкенда |
| U-2 | Исправить текущую проблему: загрузка справочных данных при проведении платежей занимает более 1 секунды | Вероятная причина — прямая интеграция интернет-банка с БД АБС |
| U-3 | Соблюдение системы дизайна компании: фирменные цвета, брендированные элементы интерфейса | Единый визуальный стиль для сайта и интернет-банка |
| | | |
| **R** | **Надёжность (Reliability)** | |
| R-1 | Все сервисы должны работать 24/7 с доступностью 99,9% | Относится к интернет-банку и новым сервисам; текущая архитектура не обеспечивает этого |
| R-2 | В случае сбоя ЦОД — переключение на резервный ЦОД с сохранением работоспособности и нагрузки | Банк располагает резервным ЦОД; интернет-банк сейчас работает в одном ЦОД |
| R-3 | Избегать прямой работы интернет-банка с API АБС в новом процессе | БД АБС перегружена; онлайн-заявки могут создать угрозу работоспособности банка |
| R-4 | При недоступности отдельных компонентов (АБС, скоринг) — корректная деградация, а не полный отказ системы | Дополнительное требование: если АБС недоступна, клиент должен видеть хотя бы каталог продуктов |
| R-5 | Кредитный конвейер и система скоринга работают 24/7 и поддерживают горизонтальное масштабирование | Эти системы готовы к росту нагрузки |
| | | |
| **P** | **Производительность (Performance)** | |
| P-1 | Время отклика для клиентских операций — в пределах миллисекунд | Требует кэширования данных, асинхронной обработки, оптимизации запросов |
| P-2 | Горизонтальное масштабирование и равномерное распределение запросов между серверами и ЦОД | Для интернет-банка и новых сервисов |
| P-3 | АБС масштабируется только вертикально из-за архитектуры БД (Oracle) | Ограничение, влияющее на выбор архитектуры интеграции |
| P-4 | Систему кредитного скоринга не нагружать дополнительными процессами предрасчёта в рабочие часы | Скоринг испытывает повышенную нагрузку днём; предрасчёты проводить в нерабочее время |
| P-5 | Обмен данными между АБС и кредитным конвейером через БД — раз в сутки; ускорить невозможно | Архитектурное ограничение, требующее альтернативного канала для срочных заявок |
| | | |
| **S** | **Поддерживаемость (Supportability)** | |
| S-1 | Максимально использовать существующие технологии банка: MS SQL, Oracle, .NET, Java, Python, React.js | Снижение стоимости внедрения и поддержки |
| S-2 | Новые технологии должны быть совместимы с существующими платформами; внутри банка должна быть экспертиза на уровне языков программирования | Критерий выбора новых компонентов |
| S-3 | При необходимости использования очередей — Kafka (на перспективу) | Текущая платформа интернет-банка (.NET Framework 4.5) несовместима с Kafka |
| S-4 | Рассмотреть перевод интернет-банка на микросервисную архитектуру в рамках задачи открытия депозитов | Поэтапная модернизация; новые микросервисы на .NET 10 рядом с монолитом |
| S-5 | Разработка документации для дальнейшего расширения системы | Обеспечение передачи знаний и масштабируемости развития |
| S-6 | Реализовать бизнес-функционал интернет-банка силами команды банка, минимизируя зависимость от подрядчика ядра | Обновление ядра привязано к подрядчику; новый функционал — через отдельные сервисы |
| | | |
| **+R** | **Ограничения (Restrictions)** | |
| +R-1 | Интернет-банк построен на платформе подрядчика: ASP.NET MVC 4.5 / .NET Framework 4.5, монолит; обновление ядра привязано к подрядчику | Ограничение на доработку существующего кода; новый функционал — через выделенные сервисы |
| +R-2 | Интеграция интернет-банка с АБС — напрямую через БД Oracle | Архитектурный долг; в новом процессе избегать такой интеграции |
| +R-3 | АБС — десктопный клиент на Delphi с логикой в PL/SQL; масштабируется только вертикально | Ограничение на производительность; новые процессы не должны увеличивать нагрузку на БД АБС |
| +R-4 | Kafka несовместим с текущей платформой интернет-банка (.NET Framework 4.5) | Требуется создание нового сервисного слоя для использования Kafka |
| +R-5 | Сотрудники бэк-офиса депозитов и кредитов не должны иметь доступ к данным друг друга (требование ИБ) | Влияет на модель данных и разграничение доступа при работе со ставками |
| +R-6 | Новые клиенты не могут быть обслужены без личной идентификации в отделении | Регуляторное ограничение банковской сферы |
| +R-7 | Передача данных с сайта и интернет-банка должна быть защищена шифрованием трафика (TLS/HTTPS) | Требование информационной безопасности для чувствительных данных |
| +R-8 | Партнёрский кол-центр — внешняя система; интеграция только через файлы (например, SFTP), без API-вызовов | Ограничение внешнего контрагента |
| +R-9 | Обмен данными между АБС и кредитным конвейером через БД — раз в сутки, ускорить невозможно | Технологическое ограничение; для срочных заявок нужен обходной путь |
| +R-10 | Систему кредитного скоринга нельзя нагружать дополнительными процессами предрасчёта в рабочие часы | Ограничение производительности; фоновые процессы — только в нерабочее время |
| +R-11 | Система кол-центра — платформа подрядчика, но команда АБС может вносить изменения (Java-стек) | Ограниченная возможность доработки; есть специалисты с Java-экспертизой |
