# ADR-002: Передача ставок по депозитам в кол-центр и партнёрский кол-центр

## Статус

Предложено

## Контекст

После запуска маркетинговой кампании по онлайн-депозитам ожидается рост звонков в кол-центр. Основная категория клиентов банка «Стандарт» — пожилые люди, которые привыкли к офлайн-обслуживанию и захотят уточнить условия по телефону.

**Проблемы:**
1. Операторы кол-центра не имеют доступа к актуальным ставкам по депозитам. Ставки рассчитываются в Excel бэк-офисом и нигде в информационных системах не ведутся централизованно.
2. Кол-центр банка может быть перегружен — необходимо подключить партнёрский кол-центр.
3. Партнёрский кол-центр — внешняя система, интеграция только через файлы (SFTP), без API.

**Контекст решения:**
В рамках MVP (ADR-001) создаётся Rate Service — единый сервис управления ставками. Текущий ADR описывает расширение этого решения для обеспечения доступа к ставкам из кол-центров.

## Use Cases

### UC-1: Консультирование клиента по ставкам оператором кол-центра банка
**Актор:** Оператор кол-центра банка
**Предусловие:** Клиент позвонил для уточнения условий депозита.
**Основной сценарий:**
1. Оператор открывает раздел «Депозитные ставки» в системе кол-центра.
2. Система отображает актуальные ставки по всем доступным депозитам.
3. Оператор консультирует клиента по условиям.
4. При необходимости оператор создаёт обращение для дальнейшей обработки.

### UC-2: Консультирование клиента оператором партнёрского кол-центра
**Актор:** Оператор партнёрского кол-центра
**Предусловие:** Клиент позвонил на линию партнёрского кол-центра.
**Основной сценарий:**
1. Оператор открывает актуальный файл со ставками в своей системе.
2. Файл содержит обновлённые ставки, полученные от банка.
3. Оператор консультирует клиента по условиям согласно скрипту.

### UC-3: Обновление ставок для партнёрского кол-центра
**Актор:** Система (автоматический процесс)
**Триггер:** Обновление ставок в Rate Service.
**Основной сценарий:**
1. Менеджер бэк-офиса обновляет ставки в Rate Service.
2. Система автоматически генерирует файл с актуальными ставками.
3. Файл передаётся на SFTP-сервер партнёрского кол-центра.
4. Партнёрский кол-центр загружает файл в свою систему.

## Функциональные требования

| ID | Требование |
|----|-----------|
| FR-1 | Система кол-центра банка отображает актуальные ставки по депозитам для операторов |
| FR-2 | Ставки в системе кол-центра обновляются автоматически при изменении в Rate Service |
| FR-3 | Партнёрский кол-центр получает файл с актуальными ставками через SFTP |
| FR-4 | Файл со ставками генерируется автоматически при обновлении ставок |
| FR-5 | Формат файла согласован с партнёрским кол-центром (CSV/XLSX) |
| FR-6 | Возможность ручной генерации и отправки файла при необходимости |

## Решение

### Архитектурный подход

Решение строится на Rate Service, созданном в рамках MVP (ADR-001), с добавлением двух каналов доставки ставок:

1. **API-канал для кол-центра банка** — система кол-центра (Java Spring Boot, микросервисы) получает ставки через REST API Rate Service. В команде АБС есть специалисты с Java-экспертизой, которые могут доработать систему кол-центра.

2. **Файловый канал для партнёрского кол-центра** — новый компонент Rate Export Service генерирует файлы со ставками и отправляет на SFTP-сервер партнёра.

### Новые компоненты

1. **Rate Export Service (.NET 10)** — подписывается на события обновления ставок в Kafka, генерирует файл (CSV/XLSX) и отправляет его на SFTP-сервер партнёрского кол-центра.

2. **Доработка системы кол-центра (Java)** — новый микросервис в системе кол-центра, который через REST API Rate Service получает актуальные ставки и предоставляет их операторам в интерфейсе.

### Интеграционная модель

```
Rate Service (.NET 10)
    │
    ├──[REST API]──→ Система кол-центра (новый микросервис, Java)
    │                    → Отображение ставок операторам в Web UI
    │
    ├──[Kafka event: rates.updated]──→ Rate Export Service (.NET 10)
    │                                      → Генерация CSV/XLSX
    │                                      → Отправка на SFTP
    │                                      → Партнёрский кол-центр
    │
    └──[Kafka event: rates.updated]──→ Notification Service
                                          → Опционально: уведомление об обновлении
```

### Взаимодействие с существующим процессом

На этапе MVP ставки по-прежнему определяются бэк-офисом. Rate Service предоставляет UI для ввода и управления ставками вместо Excel. При обновлении ставки:
1. Rate Service сохраняет новую ставку в БД.
2. Rate Service публикует событие `rates.updated` в Kafka.
3. Система кол-центра запрашивает актуальные ставки по API (при загрузке страницы или по расписанию).
4. Rate Export Service получает событие, генерирует файл, отправляет на SFTP.

### Диаграммы

Диаграммы C4 приложены отдельными файлами:
- **C4_Context_Rates.drawio** — диаграмма контекста для передачи ставок
- **C4_Component_Rates.drawio** — диаграмма компонентов

## Альтернативы

### Альтернатива 1: Передача ставок через email

Автоматическая отправка файлов со ставками по email операторам кол-центра и партнёру.

**Плюсы:** Простота реализации.
**Минусы:**
- Не автоматизирует отображение ставок в системе кол-центра.
- Зависимость от ручного процесса обработки email.
- Не масштабируется.

**Причина отклонения:** Не решает задачу автоматического отображения ставок в системах.

### Альтернатива 2: Прямой доступ кол-центра к БД Rate Service

Система кол-центра обращается напрямую к БД Rate Service.

**Плюсы:** Максимально актуальные данные.
**Минусы:**
- Прямая связь между системами через БД — антипаттерн.
- Изменение схемы БД Rate Service потребует изменений в системе кол-центра.
- Нарушает принцип инкапсуляции сервисов.

**Причина отклонения:** Создаёт жёсткую связь и нарушает микросервисные принципы.

### Альтернатива 3: Партнёрский кол-центр получает ставки через REST API

Предоставить партнёру API вместо файлов.

**Плюсы:** Более актуальные данные, стандартный подход.
**Минусы:**
- Партнёр явно указал, что готов принимать только файлы.
- Нет возможности API-вызовов с их стороны.
- Потребуется доработка внешней системы, на которую банк не влияет.

**Причина отклонения:** Техническое ограничение партнёра.

## Последствия и ограничения

### Положительные
- Операторы обоих кол-центров получают доступ к актуальным ставкам.
- Автоматизация процесса — без ручного копирования данных.
- Расширяемость: при подключении новых партнёров достаточно добавить SFTP-адресат.
- Использование существующей инфраструктуры Kafka из MVP.

### Ограничения
- Ставки в партнёрском кол-центре обновляются с задержкой (до 5 минут).
- Формат файла должен быть согласован с партнёром и зафиксирован в контракте.
- Доработка системы кол-центра зависит от доступности Java-специалистов в команде АБС.
- SFTP-канал требует мониторинга и обработки ошибок доставки.
